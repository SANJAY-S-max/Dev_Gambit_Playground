PART 1: WHAT IS A REST API?
================================================================

REST API = A web service that lets other apps communicate
           with your server using standard HTTP methods:

  GET    → Read data (e.g., get all products)
  POST   → Create new data (e.g., add a product)
  PUT    → Update existing data (e.g., update a product)
  DELETE → Delete data (e.g., delete a product)

YOUR ENDPOINTS:
  GET    /api/products              → Get all products
  GET    /api/product/{id}          → Get one product by ID
  GET    /api/product/{id}/image    → Get product image
  GET    /api/products/search?keyword=... → Search products
  POST   /api/product               → Add a new product
  PUT    /api/product/{id}          → Update a product
  DELETE /api/product/{id}          → Delete a product

Each endpoint is like a "door" that other applications
(React frontend, Postman, mobile app) can knock on.

ARCHITECTURE RULE (important for learning):
  Controller → Service → Repository → Database
  NEVER: Controller → Repository directly (bypass service)

       you add it in the Service — not scattered in controllers.

LINE BY LINE:

  @Entity
  PURPOSE: ★★ VERY IMPORTANT ★★
           "This Java class = one database table."
           Spring/JPA creates a table called "product" in MySQL.
           Class name "Product" → table name "product" (lowercase).
           WITHOUT @Entity: Just a plain Java class. No table.
           WITH @Entity: Table auto-created with all fields as columns.

  @Data (Lombok)
  PURPOSE: GENERATES ALL of the following automatically:
           - public String getName() { return this.name; }
           - public void setName(String name) { this.name = name; }
           - (same for all other fields)
           - equals() method for comparing two Product objects
           - hashCode() for use in collections like HashMap
           - toString() for printing a product as text
           WITHOUT @Data: You'd have to write ~80 lines of code!

  @AllArgsConstructor (Lombok)
  PURPOSE: Generates a constructor with ALL fields as parameters:
           public Product(int id, String name, String desc, ...) { ... }
           Lets you create a Product with all values at once.

  @NoArgsConstructor (Lombok)
  PURPOSE: Generates an empty constructor:
           public Product() { }
           JPA REQUIRES this to create empty objects before filling them!
           Without this: JPA throws an error when reading from database.

  @Id
  PURPOSE: "This field is the PRIMARY KEY of the table."
           No two products can have the same id.
           Like a unique product barcode.

  @GeneratedValue(strategy = GenerationType.IDENTITY)
  PURPOSE: FIXED — Added! Tells MySQL: "Auto-increment the id field."
           When you insert a new product WITHOUT specifying id,
           MySQL automatically assigns the next available number.
           1 → 2 → 3 → ... Never repeat.
           WITHOUT @GeneratedValue: You must manually provide an id
           every time you add a product. Very error-prone!
           WITH @GeneratedValue: MySQL handles it. Just send product data,
           and the id is auto-assigned.

  private BigDecimal price;
  PURPOSE: BigDecimal is used for MONEY values instead of float/double.
           WHY? Float/double have rounding errors!
           float price = 0.1 + 0.2 → 0.30000000000000004 (WRONG!)
           BigDecimal handles exact decimal arithmetic. No rounding errors.
           Always use BigDecimal for currency!

  @JsonFormat(shape = JsonFormat.Shape.STRING, pattern = "yyyy-MM-dd")
  private Date releaseDate;
  PURPOSE: @JsonFormat = "When converting this date to JSON, use this format."
           Without @JsonFormat: Date is shown as a Unix timestamp (number).
           With @JsonFormat: Date is shown as "2024-01-15" (readable!).
  ★ FIXED TYPO ★: Was "releaseData" (wrong!) → now "releaseDate" (correct!).
  A typo in a field name means:
  - Getter becomes getReleaseData() instead of getReleaseDate()
  - Setter becomes setReleaseData() instead of setReleaseDate()
  - JSON key becomes "releaseData" instead of "releaseDate"
  - Confusing API for users, hard to maintain!

  @Lob
  private byte[] imageData;
  PURPOSE: @Lob = "Large Object". Tells JPA/MySQL this field stores
           large binary data.
           byte[] = an array of bytes = raw binary data = an image file!
           MySQL stores this in a LONGBLOB column (can hold up to 4GB).
  ★ FIXED TYPO ★: Was "imageDate" (wrong!) → now "imageData" (correct!).
  The typo caused methods like setImageDate() (what?!) instead of
  setImageData() (makes sense!). Very confusing!

  private String imageName;
  private String imageType;
  PURPOSE: Store metadata ABOUT the image:
           imageName = "laptop.jpg"
           imageType = "image/jpeg"
           imageData = the actual binary bytes of the image
           The type is needed to tell the browser: "This is a JPEG image."
           The name helps the user know what file they uploaded.

  @Repository
  public interface ProductRepo extends JpaRepository<Product, Integer> {

      @Query("SELECT p FROM Product p WHERE " +
             "LOWER(p.name) LIKE LOWER(CONCAT('%', :keyword, '%')) OR " +
             "LOWER(p.description) LIKE LOWER(CONCAT('%', :keyword, '%')) OR " +
             "LOWER(p.brand) LIKE LOWER(CONCAT('%', :keyword, '%')) OR " +
             "LOWER(p.category) LIKE LOWER(CONCAT('%', :keyword, '%'))")
      List<Product> searchProducts(@Param("keyword") String keyword);
  }

LINE BY LINE:

  @Repository
  PURPOSE: Tells Spring: "This is a database access class."
           Spring creates an implementation automatically.
           Also enables database error translation.

  public interface ProductRepo extends JpaRepository<Product, Integer>
  PURPOSE: You get ALL these methods FREE from JpaRepository:
           - save(product)          → INSERT or UPDATE
           - findById(1)            → SELECT WHERE id = 1
           - findAll()              → SELECT * FROM product
           - deleteById(1)          → DELETE WHERE id = 1
           - count()                → SELECT COUNT(*)
           All working with ZERO code from you!
           <Product, Integer> = working with Product table, ID is Integer.

  @Query("SELECT p FROM Product p WHERE ...")
  PURPOSE: ★★ CUSTOM JPQL QUERY ★★
           JPQL = JPA Query Language. Similar to SQL but uses JAVA
           CLASS NAMES instead of TABLE NAMES.
           
           "SELECT p FROM Product p" = Select all Products (Java class)
           "WHERE" = filter condition
           
           LOWER(p.name) LIKE LOWER(CONCAT('%', :keyword, '%'))
           = Case-insensitive search for keyword in name
           LOWER() = convert to lowercase before comparing
           LIKE = SQL pattern matching
           % = wildcard (any characters)
           CONCAT('%', :keyword, '%') = "%laptop%" = anything containing "laptop"
           
           So "LOWER(name) LIKE LOWER('%laptop%')" means:
           "Name contains 'laptop' (case-insensitive)"
           
           OR = search in name OR description OR brand OR category
           If keyword is in ANY of these → product matches!
           
           :keyword = a named parameter (replaced with actual value)

  @Param("keyword") String keyword
  PURPOSE: Tells Spring: "The :keyword in @Query maps to this parameter."
           When you call searchProducts("laptop"):
           :keyword gets replaced with "laptop"
           → LOWER(p.name) LIKE LOWER('%laptop%')

  @Autowired private ProductRepo repo;

  public List<Product> getAllProducts()

  public Product getProductById(int id)

ANNOTATION EXPLANATIONS:

  @RestController
  PURPOSE: "This class handles HTTP requests and returns JSON/text."
           Combination of @Controller + @ResponseBody.
           @Controller = "handles web requests"
           @ResponseBody = "return data directly, not a view/HTML page"

  @CrossOrigin
  PURPOSE: Allow requests from any domain/port.
           Without this: browser's Same-Origin Policy blocks requests
           from your React frontend (port 3000) to your API (port 8080).
           @CrossOrigin("*") = allow from ANYWHERE.
           ⚠️ Restrict to specific domains in production!

  @RequestMapping("/api")
  PURPOSE: Base URL prefix. ALL methods in this class start with "/api".
           @GetMapping("/products") → actual URL: GET /api/products
           @PostMapping("/product") → actual URL: POST /api/product

  @Autowired ProductService service;
  PURPOSE: Dependency Injection. Spring injects the ProductService.
           Controller delegates ALL logic to the service.
           Controller only handles: parsing requests, calling service,
           wrapping response. NEVER puts business logic here.

ENDPOINT EXPLANATIONS:

  @GetMapping("/")
  return "hello world";
  PURPOSE: A simple health-check endpoint.
           Visit http://localhost:8080/api/ → see "hello world"
           Useful for checking if the server is running.

  @GetMapping("/products") — getAllProduct()
  PURPOSE: Return ALL products in the database.
           ResponseEntity<List<Product>> = "Return a list of products with HTTP status."
           HttpStatus.OK = 200 → "Everything worked fine."

  ResponseEntity:
  PURPOSE: A WRAPPER that lets you control the HTTP response:
           - Set the response BODY (data)
           - Set the HTTP STATUS CODE (200, 404, 201, 500, etc.)
           Without ResponseEntity: always returns 200.
           With ResponseEntity: you decide what status to return.

  @GetMapping("/product/{id}") — getProduct()
  @PathVariable int id
  PURPOSE: {id} is a URL VARIABLE. 
           URL: GET /api/product/5 → id = 5
           @PathVariable extracts "5" from the URL and gives it to the method.
           Then we look up the product with id=5 in the database.

  if (product != null) → HttpStatus.OK (200)
  else → HttpStatus.NOT_FOUND (404)
  PURPOSE: Return 200 if found, 404 if not.
           After the fix to service.getProductById() (returning null instead
           of new Product()), this null check now works correctly.

  @PostMapping("/product") — addProduct()
  @RequestPart Product product
  @RequestPart MultipartFile imageFile
  PURPOSE: @RequestPart = read a PART of a multipart/form-data request.
           Multipart = request with BOTH JSON data AND file upload together.
           You send the product as one part (JSON) and the image as another part.
           Spring automatically converts the JSON part to a Product object.
           Spring gives the file part as a MultipartFile object.
           
  try { ... } catch (Exception e) { return ...INTERNAL_SERVER_ERROR }
  PURPOSE: If ANYTHING fails (disk error, DB error, etc.):
           Return HTTP 500 Internal Server Error with the error message.
           Without try-catch: Exception would crash the request with no nice response.

  HttpStatus.CREATED (201):
  PURPOSE: "201 Created" = "Resource was successfully created."
           More specific than 200. Tells the caller: "New product was made."

  @GetMapping("/product/{productId}/image") — getImageByProductId()
  ★ FIXED: Added null check before accessing image data ★
  PURPOSE: Return the raw image bytes so the browser can display the image.
           if (product == null) → return 404. Without this check:
           product.getImageData() would throw NullPointerException → 500 error!
           
  ResponseEntity.ok()
      .contentType(MediaType.valueOf(product.getImageType()))
      .body(imageFile)
  PURPOSE: "Return the image bytes with the correct Content-Type header."
           .contentType("image/jpeg") tells the browser: "This is a JPEG image."
           Browser then renders it as an image instead of binary garbage.

  @PutMapping("/product/{id}") — updateProduct()
  PURPOSE: Update an existing product.
           @PathVariable int id = which product to update
           @RequestPart Product product = new product data
           @RequestPart MultipartFile imageFile = new image
           throws IOException = declared because getBytes() can throw it.

  @DeleteMapping("/product/{id}") — deleteProduct()
  ★ FIXED: Was returning HttpStatus.BAD_REQUEST for not found ★
  PURPOSE: Delete product by ID.
           BEFORE: If not found → return BAD_REQUEST (400) — semantically wrong!
                   400 Bad Request means the CLIENT did something wrong.
                   But the client did nothing wrong — the product just doesn't exist!
           AFTER:  If not found → return NOT_FOUND (404) — correct!
                   404 = "The thing you asked for doesn't exist."

  @GetMapping("/products/search") — searchProduct()
  ★ FIXED: Duplicate @GetMapping("/products") bug ★
  BEFORE: The original code had:
    @GetMapping("/products") getAllProduct()    ← first mapping
    @GetMapping("/products") searchProduct()   ← DUPLICATE mapping!
    Spring throws: "AmbiguousHandlerMappingException" → APP CANNOT START!
  AFTER: Search moved to /api/products/search
    @GetMapping("/products")        getAllProduct()   ← get all
    @GetMapping("/products/search") searchProduct()  ← search

  ★ ALSO FIXED: @RequestParam annotation added ★
  BEFORE: public ResponseEntity<List<Product>> searchProduct(String keyword)
          No annotation on 'keyword' → Spring has no idea where to get it!
          HTTP requests don't magically find "keyword" from thin air.
  AFTER:  public ... searchProduct(@RequestParam String keyword)
          @RequestParam = "Get 'keyword' from the URL query string."
          URL: GET /api/products/search?keyword=laptop
          @RequestParam extracts "laptop" from "?keyword=laptop"

PART 4: HOW MULTIPART FILE UPLOAD WORKS
================================================================

When you add a product with an image, the request is a
"multipart/form-data" request. It's like sending multiple parts:

  HTTP Request:
    POST /api/product
    Content-Type: multipart/form-data

    --boundary
    Content-Disposition: form-data; name="product"
    Content-Type: application/json

    {"name": "Gaming Laptop", "price": 75000.00, ...}

    --boundary
    Content-Disposition: form-data; name="imageFile"; filename="laptop.jpg"
    Content-Type: image/jpeg

    <binary image data>
    --boundary--

In Postman:
  - Select "form-data" in Body tab
  - Add key "product" (type: Text), value: {"name":"Laptop",...}
  - Add key "imageFile" (type: File), value: select your image file

Spring reads:
  @RequestPart Product product   → Reads the "product" part as JSON → Java object
  @RequestPart MultipartFile imageFile → Reads the "imageFile" part as file

The service then extracts:
  imageFile.getOriginalFilename() → "laptop.jpg"
  imageFile.getContentType()      → "image/jpeg"
  imageFile.getBytes()            → [binary data as byte[]]

These get stored in the Product's fields (imageName, imageType, imageData).

PART 7: KEY CONCEPTS QUICK REFERENCE
================================================================

@Entity:
  Maps a Java class to a MySQL table.
  Class name → table name (lowercase).
  Fields → columns.

@Id + @GeneratedValue:
  @Id = primary key column.
  @GeneratedValue = let database auto-assign the next number.

Lombok Annotations:
  @Data = generates all getters, setters, equals, hashCode, toString.
  @AllArgsConstructor = generates constructor with all fields.
  @NoArgsConstructor = generates empty constructor (required by JPA).

ResponseEntity<T>:
  Wraps your response body + HTTP status code.
  new ResponseEntity<>(body, HttpStatus.OK) = 200 with body.
  new ResponseEntity<>(HttpStatus.NOT_FOUND) = 404 no body.

@PathVariable:
  Extracts value from URL path: /product/{id} → id
  GET /product/5 → id = 5

@RequestParam:
  Extracts value from query string: ?keyword=laptop → keyword
  GET /products/search?keyword=laptop → keyword = "laptop"

@RequestPart:
  Extracts part from multipart/form-data request.
  Used for file uploads combined with JSON data.

MultipartFile:
  Represents an uploaded file.
  .getBytes() = raw binary content
  .getContentType() = "image/jpeg" etc.
  .getOriginalFilename() = "photo.jpg" etc.

@Lob:
  "Large Object" — stores binary data.
  byte[] imageData = stores image as raw bytes in MySQL LONGBLOB column.

BigDecimal:
  Exact decimal numbers. Use for money/prices.
  float/double have rounding errors. BigDecimal does not.

@JsonFormat:
  Controls how a field appears in JSON.
  Date → "2024-01-15" instead of Unix timestamp number.

Optional.orElse(null):
  Returns the value if present, otherwise returns null.
  Better than crashing with NoSuchElementException.
