PART 1: WHAT HAPPENS WHEN A REQUEST COMES IN?
         (The Filter System — Very Important!)
================================================================

When you type a URL in Postman and press Send,
your request travels like this:

  YOU (Postman)
        |
        | sends HTTP request + JWT token in header
        v
  ┌─────────────────────────────────────────────────────┐
  │              YOUR SPRING BOOT APP                   │
  │                                                     │
  │  ┌──────────────────────────────────────────────┐   │
  │  │         FILTER CHAIN (Security Checks)       │   │
  │  │                                              │   │
  │  │  Filter 1: CorsFilter (cross-origin check)   │   │
  │  │  Filter 2: ★ JwtFilter ★ (YOUR CUSTOM!)     │   │
  │  │            → Read "Authorization: Bearer..." │   │
  │  │            → Extract JWT token               │   │
  │  │            → Validate token (not expired)    │   │
  │  │            → Set authentication in context   │   │
  │  │  Filter 3: UsernamePasswordAuthFilter        │   │
  │  │  Filter 4: Other Spring Security filters...  │   │
  │  │                                              │   │
  │  └──────────────────────┬───────────────────────┘   │
  │                         |                           │
  │                         | (only if all filters OK)  │
  │                         v                           │
  │  ┌──────────────────────────────────────────────┐   │
  │  │      DISPATCHER SERVLET (Traffic Cop)        │   │
  │  │  Reads the URL and routes to the right       │   │
  │  │  Controller method                           │   │
  │  └──────────────────────┬───────────────────────┘   │
  │                         |                           │
  │                         v                           │
  │  ┌──────────────────────────────────────────────┐   │
  │  │         YOUR CONTROLLER                      │   │
  │  │  (HelloController / StudentController /      │   │
  │  │   UserController)                            │   │
  │  │  This is where YOUR code runs                │   │
  │  └──────────────────────────────────────────────┘   │
  └─────────────────────────────────────────────────────┘

KEY POINT:
  Filters run BEFORE your controller.
  JwtFilter runs first and reads the JWT token.
  If token is valid → request is "authenticated".
  If no token or bad token → Spring returns 401 Unauthorized.

Think of it like:
  JWT Token = Your Office ID Card
  JwtFilter = The ID card scanner at the door
  Controller = Your work desk inside the office
  You can't reach your desk without scanning your card!

PART 2: WHAT IS JWT? (JSON Web Token)
================================================================

JWT is a secure "digital pass" that proves who you are.

It looks like this:
  eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiJzYW5qYXkiLCJpYXQiOjE...

It has THREE parts separated by dots (.):

  PART 1 — HEADER (tells the algorithm used):
    Base64({ "alg": "HS256", "typ": "JWT" })
    → eyJhbGciOiJIUzI1NiJ9

  PART 2 — PAYLOAD (the actual data — who you are, when it expires):
    Base64({ "sub": "sanjay", "iat": 1696000000, "exp": 1696036000 })
    → eyJzdWIiOiJzYW5qYXkiLCJpYXQiOjE...
    
    sub = subject = username
    iat = issued at = time of creation
    exp = expiration = when it becomes invalid

  PART 3 — SIGNATURE (proves the token wasn't tampered with):
    HMAC_SHA256(base64(header) + "." + base64(payload), secretKey)
    → Only your server knows the secretKey, so only it can make valid tokens!

WHY JWT IS BETTER THAN BASIC AUTH:
  ❌ Basic Auth: Send username+password in EVERY request
               If intercepted by hacker → they have your password!
  ✓ JWT:       Login ONCE → get short-lived token (10 hours)
               Send only the token in every request
               Token expires → attacker can't reuse it
               Even if intercepted → it expires soon

REAL WORLD EXAMPLE:
  Think of Users.java as a FORM TEMPLATE.
  @Entity tells Spring: "Create a database table based on this form."
  Each field (id, username, password) = one column in the table.

LINE BY LINE:

  @Entity
  PURPOSE: ★★ VERY IMPORTANT ★★
           Tells JPA/Hibernate: "Map this Java class to a database table."
           Spring auto-creates a table called "users" in MySQL.
           (Java class name "Users" → table name "users")
           WITHOUT @Entity: Just a plain Java class, no table created.
           WITH @Entity: MySQL gets a "users" table automatically!

  @Id
  private int id;
  PURPOSE: @Id = "This field is the PRIMARY KEY of the table."
           Primary Key = Unique identifier for each row.
           Like your bank account number — no two users share it.
           The MySQL table gets a "id" column marked as PRIMARY KEY.

  NOTE: In the fixed version, we kept int id without @GeneratedValue
  for simplicity, but the caller (UserController via UserService) must
  provide a unique id when registering. In real production apps you would
  add @GeneratedValue(strategy = GenerationType.IDENTITY) so MySQL
  auto-assigns the next number (1, 2, 3...) automatically.

  private String username;
  private String password;
  PURPOSE: These become VARCHAR columns in the users table.
           "private" = only this class accesses them directly.
           Outsiders must use getters/setters to read/write.

  public Users() { }
  PURPOSE: JPA REQUIRES an empty constructor!
           When JPA reads a row from the database, it:
           1. Calls Users() to create an empty object
           2. Calls setUsername("sanjay") to fill username
           3. Calls setPassword("$2a$...") to fill password
           If you remove this constructor: JPA throws an error!

FULL CODE:
  public class UserPrincipal implements UserDetails {
      private Users user;

      public UserPrincipal(Users user) {
          this.user = user;
      }

      @Override
      public Collection<? extends GrantedAuthority> getAuthorities() {
          return Collections.singleton(new SimpleGrantedAuthority("ROLE_USER"));
      }

      @Override
      public String getPassword() { return user.getPassword(); }

      @Override
      public String getUsername() { return user.getUsername(); }

      @Override public boolean isAccountNonExpired()   { return true; }
      @Override public boolean isAccountNonLocked()    { return true; }
      @Override public boolean isCredentialsNonExpired(){ return true; }
      @Override public boolean isEnabled()             { return true; }
  }

WHY DOES THIS CLASS EXIST?
  Spring Security only understands the UserDetails interface.
  Your Users class doesn't implement UserDetails.
  UserPrincipal is the BRIDGE — it wraps Users and speaks UserDetails.

  ANALOGY: You're Indian, applying for a job in Japan.
  Japan's HR system only accepts resumes in Japanese format (UserDetails).
  Your resume is in English (Users class).
  UserPrincipal = the translator who converts your resume to Japanese.

LINE BY LINE:

  implements UserDetails
  PURPOSE: Signing a CONTRACT with Spring Security.
           UserDetails has 7 required methods you MUST implement:
           - getAuthorities(), getPassword(), getUsername()
           - isAccountNonExpired(), isAccountNonLocked()
           - isCredentialsNonExpired(), isEnabled()

  new SimpleGrantedAuthority("ROLE_USER")
  PURPOSE: ★ FIXED: Was "USER", now correctly "ROLE_USER" ★
           Spring Security REQUIRES the "ROLE_" prefix.
           Without the prefix, hasRole("USER") checks won't work.
           This gives every user the "ROLE_USER" permission level.
           REAL APPS: Admin users get "ROLE_ADMIN", etc.

  getPassword() { return user.getPassword(); }
  PURPOSE: Spring Security calls this when verifying login.
           Returns the BCrypt-hashed password from the Users object.
           Spring then compares: BCrypt.matches(typed, stored)

  isAccountNonExpired(), isAccountNonLocked(), etc.
  PURPOSE: Extra account status checks. All return true = everything OK.
           REAL APPS: Check actual database flags for these values.
           Here: simplified for learning — always all good.

FILE 9: JWTService.java (The JWT Factory) — NEW!

FULL CODE:
  @Service
  public class JWTService {

      private String secretKey;

      public JWTService() throws NoSuchAlgorithmException {
          KeyGenerator keyGen = KeyGenerator.getInstance("HmacSHA256");
          SecretKey sK = keyGen.generateKey();
          secretKey = Base64.getEncoder().encodeToString(sK.getEncoded());
      }

      public String generateToken(String userName) {
          Map<String, Object> claims = new HashMap<>();
          return Jwts.builder()
                  .claims().add(claims).subject(userName)
                  .issuedAt(new Date(System.currentTimeMillis()))
                  .expiration(new Date(System.currentTimeMillis() + 1000L * 60 * 60 * 10))
                  .and()
                  .signWith(getKey())
                  .compact();
      }

      private Key getKey() {
          byte[] keyBytes = Decoders.BASE64.decode(secretKey);
          return Keys.hmacShaKeyFor(keyBytes);
      }

      public String extractUserName(String token) {
          return extractClaim(token, Claims::getSubject);
      }

      public <T> T extractClaim(String token, Function<Claims, T> claimsResolver) {
          final Claims claims = extractAllClaims(token);
          return claimsResolver.apply(claims);
      }

      private Claims extractAllClaims(String token) {
          return Jwts.parser()
                  .verifyWith((SecretKey) getKey())
                  .build()
                  .parseSignedClaims(token)
                  .getPayload();
      }

      public boolean validateToken(String token, UserDetails userDetails) {
          final String userName = extractUserName(token);
          return (userName.equals(userDetails.getUsername()) && !isTokenExpired(token));
      }

      private boolean isTokenExpired(String token) {
          return extractExpiration(token).before(new Date());
      }

      private Date extractExpiration(String token) {
          return extractClaim(token, Claims::getExpiration);
      }
  }

REAL WORLD EXAMPLE:
  Think of JWTService as a BANK THAT ISSUES ATM CARDS.
  generateToken() = "Here is your ATM card (JWT token)"
  validateToken() = "Let me verify this ATM card is real and not expired"
  extractUserName() = "Let me see whose name is on the card"

LINE BY LINE:

  private String secretKey;
  PURPOSE: The private signing key for JWT tokens.
           This key PROVES the token came from YOUR server.
           If an attacker makes a fake token, they can't sign it
           correctly without knowing this secret key.
           IMPORTANT: This key is regenerated every time the app
           restarts. So old tokens become invalid after restart.
           In production: Store this key in a fixed config/env variable!

  KeyGenerator.getInstance("HmacSHA256")
  PURPOSE: Creates a random cryptographic key generator using
           HmacSHA256 algorithm (a very strong signing algorithm).
           "Hmac" = Hash-based Message Authentication Code.
           "SHA256" = Secure Hash Algorithm 256-bit.

  Base64.getEncoder().encodeToString(sK.getEncoded())
  PURPOSE: Converts the binary secret key into a safe text string.
           Base64 is a way to represent binary data as plain text.
           Like converting a photo (binary) to text for email attachment.

  Jwts.builder()
  PURPOSE: Start building a JWT token using the JJWT library.

  .claims().add(claims)
  PURPOSE: Add extra data (claims) to the token.
           Here "claims" is empty (HashMap) — no extra data.
           In real apps you might add: user roles, user email, etc.

  .subject(userName)
  PURPOSE: Set the "sub" (subject) field in the token = the username.
           This is WHO this token belongs to.
           Example: sub = "sanjay"

  .issuedAt(new Date(System.currentTimeMillis()))
  PURPOSE: Record WHEN the token was created.
           "iat" field in JWT = issued at.
           Example: iat = 1696000000 (Unix timestamp)

  .expiration(new Date(System.currentTimeMillis() + 1000L * 60 * 60 * 10))
  ★ FIXED BUG ★
  PURPOSE: Set WHEN the token expires.
           1000L * 60 * 60 * 10 = 10 hours in milliseconds
           (1000ms = 1s, 60s = 1min, 60min = 1hr, 10hr)
           Why "L"? Forces Java to use long (64-bit) instead of int (32-bit).
           Without L: int * int * int * int → INTEGER OVERFLOW → WRONG TIME!
           With L: everything calculated as long → CORRECT!

           OLD CODE BUG: System.currentTimeMillis() * 60 * 60 * 10
           This MULTIPLIED the current timestamp instead of ADDING!
           Current time is ~1.7 trillion milliseconds.
           1.7 trillion * 60 * 60 * 10 = ASTRONOMICAL number → broken!

  .and().signWith(getKey())
  PURPOSE: Digitally sign the token with our secret key.
           This is the MAGIC of JWT security.
           Anyone can READ the token (it's Base64, not encrypted).
           But NO ONE can MODIFY it without breaking the signature.
           If they change even ONE character → signature mismatch → rejected!

  .compact()
  PURPOSE: Finalize and return the complete JWT string.
           Returns something like:
           "eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiJzYW5qYXkiLCJpYXQiO..."

  ★ REMOVED BUG ★ — The old code had:
    return Jwts.builder()...compact();   ← first return
    return "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...";  ← second return!
    This is UNREACHABLE CODE — Java never reaches it.
    It's also hardcoded nonsense. Compile error! Removed it.

  extractUserName(String token)
  ★ FIXED ★ — Was: return "";  (hardcoded empty string!)
  NOW: return extractClaim(token, Claims::getSubject);
  PURPOSE: Actually read the "sub" field from the JWT.
           Claims::getSubject is a method reference.
           It means: "call the getSubject() method on the Claims object."
           The extracted username is used by JwtFilter to identify the user.

  extractClaim(token, Function<Claims, T> claimsResolver)
  PURPOSE: Generic helper method to extract ANY claim from a JWT.
           "Function<Claims, T>" = a function that takes Claims and returns T.
           This makes the code reusable — same method can extract
           username, expiration date, or any other claim.

  extractAllClaims(String token)

           .expiration(new Date(System.currentTimeMillis() * 60 * 60 * 10))
           currentTimeMillis() ≈ 1,700,000,000,000 (1.7 trillion)
           Multiplying by 60*60*10 = 36000 → OVERFLOWS long!
           Result is a random garbage time far in past/future.
           Fix: + 1000L * 60 * 60 * 10 (ADD 10 hours, don't multiply)
           "L" forces long arithmetic to prevent overflow.

  BUG 13: JWTService.java — extractUserName() was a stub
           return "";  ← Always returns empty string!
           JwtFilter extracts "" as username → null check fails → never authenticates!
           Fix: Implemented real extraction using Claims::getSubject.

  BUG 14: JWTService.java — validateToken() was a stub
           return true;  ← Always returns true! Any token works.
           Expired tokens work. Forged tokens work. No real security!
           Fix: Implemented real validation: checks username + expiry.

  BUG 15: JWTService.java — Wrong import (org.apache.catalina.User)
           This is a Tomcat internal class. Completely wrong!
           Not even used in the code.
           Fix: Removed the import.

  BUG 16: UserService.java — Wrong return type for authenticate()
           AuthenticationManager authentication = authManager.authenticate(...)
           authenticate() returns Authentication, NOT AuthenticationManager!
           Fix: Authentication authentication = authManager.authenticate(...)

  BUG 17: UserService.java — generateToken() called without argument
           jwtService.generateToken()  ← method needs String userName!
           Fix: jwtService.generateToken(user.getUsername())

  BUG 18: UserPrincipal.java — Wrong role format
           new SimpleGrantedAuthority("USER")  ← missing "ROLE_" prefix!
           Spring Security's hasRole() automatically adds "ROLE_".
           Without the prefix: role-based access controls don't work.
           Fix: new SimpleGrantedAuthority("ROLE_USER")

PART 7: KEY CONCEPTS QUICK REFERENCE
================================================================

JWT (JSON Web Token):
  A self-contained digital pass.
  Structure: header.payload.signature (Base64 encoded)
  Server creates it → gives to client → client sends it every request.
  Server reads it → verifies signature → trusts the contents.

@Bean:
  A method that creates an object managed by Spring.
  Other parts can @Autowired these objects.

@Autowired:
  "Spring, inject the right object here. I don't create it myself."
  This is Dependency Injection — the heart of Spring.

@Component / @Service / @Repository / @Controller / @RestController:
  All tell Spring: "Create ONE instance of this class and manage it."
  @Service = business logic layer.
  @Repository = database layer.
  @RestController = web request handler.
  @Component = generic Spring-managed class (like JwtFilter).

Filter Chain:
  A series of checks every request must pass through.
  Filters run in order. Any filter can reject the request.
  JwtFilter is added to this chain via .addFilterBefore().

SecurityContextHolder:
  Spring Security's in-memory holder for "who is currently logged in."
  JwtFilter sets authentication here → all security checks see this user.
  Cleared after each request (since we're STATELESS).

BCrypt:
  A password hashing algorithm. One-way: can hash but cannot unhash.
  To verify: hash the input and compare with stored hash.
  Strength 12 = 2^12 = 4096 rounds of hashing. Very secure, somewhat slow.

STATELESS vs STATEFUL:
  STATEFUL: Server remembers sessions. Uses cookies. Traditional websites.
  STATELESS: Server remembers NOTHING. Client sends token every request.
             REST APIs are always stateless. JWTs enable statelessness.

extends vs implements:
  extends → Class inherits from Class (gets all methods).
  extends → Interface inherits from Interface.
  implements → Class fulfills a Contract (Interface).
  A class can only extend ONE class.
  A class can implement MANY interfaces.

Checked vs Unchecked Exceptions:
  Checked = Must be declared with "throws" or caught with try/catch.
            Example: IOException, NoSuchAlgorithmException.
  Unchecked = No need to declare. Example: NullPointerException.
  authManager.authenticate() throws checked exception → need throws Exception!

PART 8: HOW TO TEST THIS API (Postman Guide)
================================================================

STEP 1: Start MySQL server and create database:
  CREATE DATABASE my_database;

STEP 2: Start the Spring Boot app.
  Check console: "Started SpringSecurityApplication on port 8080"

STEP 3: Register a user:
  Method: POST
  URL: http://localhost:8080/user/register
  Body (JSON):
    {"id": 1, "username": "sanjay", "password": "S@123"}
  Response: User object with hashed password.

STEP 4: Login to get JWT token:
  Method: POST
  URL: http://localhost:8080/user/login
  Body (JSON):
    {"username": "sanjay", "password": "S@123"}
  Response: "eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiJzYW5qYXki..."
  COPY THIS TOKEN!

STEP 5: Access protected endpoint:
  Method: GET
  URL: http://localhost:8080/students
  Headers:
    Key: Authorization
    Value: Bearer eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiJzYW5qYXki...
           (paste your token after "Bearer ")
  Response: List of students as JSON.

STEP 6: Try without token:
  Same request but remove the Authorization header.
  Response: 401 Unauthorized ← correct! Spring Security blocks it.
